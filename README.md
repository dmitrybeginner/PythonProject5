# Образовательная платформа

Этот проект представляет собой образовательную платформу, разработанную на Django.

## Запуск проекта с помощью Docker

Для запуска проекта у вас должны быть установлены Docker и Docker Compose.

### 1. Переменные окружения

Перед запуском необходимо создать файл `.env` с переменными окружения. Вы можете использовать предоставленный шаблон `.env.template`.

```bash
cp .env.template .env
```

Убедитесь, что вы заполнили необходимые значения в файле `.env`, такие как `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`, `SECRET_KEY` и т.д.

### 2. Сборка и запуск контейнеров

Чтобы собрать и запустить все сервисы проекта в фоновом режиме, используйте следующую команду:

```bash
docker-compose up --build -d
```

### 3. Проверка статуса сервисов

Вы можете проверить статус всех запущенных сервисов с помощью команды:

```bash
docker-compose ps
```

Вы должны увидеть следующие запущенные сервисы: `db`, `redis`, `app`, `celery`, `celery_beat`, `nginx`.

Для просмотра логов определенного сервиса используйте команду:

```bash
docker-compose logs <имя_сервиса>
```

Например, для просмотра логов основного приложения:

```bash
docker-compose logs app
```

### 4. Доступ к приложению

После того как сервис `app` будет запущен, вы сможете получить доступ к приложению в вашем браузере по адресу:

[http://localhost](http://localhost)

### 5. Остановка проекта

Чтобы остановить все сервисы и удалить контейнеры, используйте команду:

```bash
docker-compose down
```

## Настройка CI/CD и деплоя на удаленный сервер

Для автоматического тестирования, сборки и деплоя проекта используется GitHub Actions. Деплой осуществляется на удаленный сервер с использованием Docker Compose.

### 1. Настройка удаленного сервера

Убедитесь, что на вашем удаленном сервере установлены Docker и Docker Compose.

### 2. Настройка GitHub Secrets

Для корректной работы CI/CD и деплоя необходимо настроить следующие секреты в вашем репозитории GitHub (Settings -> Secrets and variables -> Actions -> New repository secret):

*   `DOCKER_HUB_USERNAME`: Ваш логин Docker Hub.
*   `DOCKER_HUB_ACCESS_TOKEN`: Токен доступа Docker Hub (можно сгенерировать в настройках Docker Hub).
*   `SSH_KEY`: Приватный SSH-ключ для доступа к удаленному серверу.
*   `SSH_USER`: Имя пользователя для SSH-подключения к удаленному серверу.
*   `SERVER_IP`: IP-адрес вашего удаленного сервера.
*   `DEPLOY_DIR`: Директория на удаленном сервере, куда будет деплоиться проект (например, `/home/user/my_project`).
*   `PRODUCTION_ENV_FILE`: Содержимое файла `.env` для продакшен-окружения на сервере. Убедитесь, что все чувствительные данные (ключи API, пароли к БД и т.д.) указаны здесь.

### 3. Workflow GitHub Actions

Файл `.github/workflows/ci-cd.yml` содержит конфигурацию CI/CD. Он выполняет следующие шаги:
*   **Linting:** Проверка кода на соответствие стилю с помощью Flake8.
*   **Testing:** Запуск тестов с покрытием кода.
*   **Docker Build Check:** Проверка возможности сборки Docker-образов (запускается на Pull Request).
*   **Build and Push:** Сборка Docker-образов и их публикация в Docker Hub (запускается при push в ветку `develop`).
*   **Deploy:** Автоматический деплой на удаленный сервер (запускается при push в ветку `develop`).

### 4. Адрес развернутого приложения

Приложение будет доступно по адресу: `http://ВАШ_IP_СЕРВЕРА` (замените на актуальный IP-адрес вашего сервера).
